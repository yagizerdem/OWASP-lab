Real code, real vulnerabilities

No quizzes and no mock data. Each lab is a normal ASP.NET Core service running against a live SQL Server, so what you exploit is what you then fix.

  • Full source code and git history for every lab
  • Plain HTTP endpoints you can hit with curl or any REST client
  • Seeded dummy data so every exploit has something to find

Every lab follows the same three steps

  1. 1Run

    Start every lab with one docker compose up command. Each service starts with its own database and seeded dummy data, entirely on your machine.

  2. 2Exploit

    Intercept requests, craft malicious payloads, and watch flawed logic hand over accounts, data, or full query control. curl or any REST client is enough.

  3. 3Fix

    Find the root cause in the source, write the secure ASP.NET Core version, and send the same payload again to confirm it no longer works.

Start with the first category

Clone the repository, bring up the ten services, and work through the attack and the fix for each category at your own pace.
